# AETHER X Governed Intelligence — Limitations & Unsupported Uses

`DEV-GATE-04 CANDIDATE · PUBLIC ENGINEERING BOUNDARY · NON-PRODUCTION`

This document states what the current public developer surface does **not** establish or support.

The purpose is to prevent successful examples, tests or CI runs from being generalized beyond their evidence.

## 1. Current Maturity

The public repository currently contains:

- conceptual/non-product-specific specifications;
- machine-readable public structural contracts;
- bounded non-production reference validators;
- synthetic public conformance kits;
- a repository-local Python SDK candidate;
- a validated non-published engineering release candidate;
- public CI/governance evidence.

It does **not** contain an officially supported public SDK.

```text
SDK PUBLICATION: NOT AUTHORIZED
```

## 2. Unsupported Distribution Assumptions

The current candidate is not:

- an approved PyPI package;
- an approved package under any other registry;
- an approved package identity or namespace;
- a generally redistributable open-source package;
- covered by a public software reuse licence;
- a supported binary or wheel distribution.

`PUBLIC VISIBILITY ≠ SOFTWARE REUSE LICENCE`

## 3. Unsupported Production Assumptions

The public candidate is not represented as:

- production-ready;
- suitable for unsupervised consequential execution;
- a production authorization service;
- a production agent runtime;
- a credential-management system;
- a production policy engine;
- a production data-quality system;
- a production API/service;
- a customer deployment.

## 4. No Real-World Execution Surface

The candidate performs validation over public contract payloads.

It does not:

- place trades;
- move money;
- call brokers;
- call AETHER X private systems;
- execute enterprise actions;
- issue real authority grants;
- invoke external tools;
- manage real credentials;
- make network calls as part of the bounded SDK-candidate facade.

`VALIDATION RESULT ≠ EXECUTION AUTHORITY`

## 5. Bounded Contract Coverage

The candidate currently handles only:

```text
AX-PUB-SPEC-002 v1.0
AX-PUB-SPEC-003 v1.0
AX-PUB-SPEC-004 v1.0
```

Other contract IDs or versions are outside the declared candidate surface.

A successful validation does not mean every possible semantic, legal, operational or domain-specific requirement has been validated.

## 6. Reference / Synthetic Evidence Boundary

Public examples and conformance vectors are generic or synthetic.

They do not establish:

- production data quality;
- scientific validity of a private research program;
- customer-specific correctness;
- financial predictive performance;
- real-world agent safety;
- real-world tool reliability;
- regulatory suitability.

## 7. Runtime Compatibility Boundary

Direct CI evidence currently covers the bounded candidate on:

```text
Python 3.10
Python 3.11
Python 3.12
Python 3.13
```

This is not a general Python support commitment.

Runtimes outside that matrix are not represented as verified by the current candidate evidence.

## 8. Security Boundary

Current CI includes bounded public/private dependency checks and Gate-03 build-provenance/SBOM evidence.

This does not establish:

- security certification;
- penetration-test completion;
- vulnerability-free software;
- regulatory compliance;
- standards certification;
- a public bug-bounty program;
- a security-response SLA.

`ATTESTED BUILD ≠ SECURITY CERTIFICATION`

## 9. No Product Integration Claim

Nothing in the public repository establishes integration with:

- AETHER X Quantum;
- AX-OS;
- AIC;
- AETHER X Research;
- any other private AETHER X initiative.

Shared company ownership, doctrine or terminology does not imply a shared runtime or deployment dependency.

## 10. No External Adoption Claim

DEV-GATE-04 is an external-evaluation-readiness gate.

Until separately evidenced, AETHER X does not claim from this repository that:

- an external developer completed evaluation;
- a partner integrated the candidate;
- a customer uses the candidate;
- an evaluator endorsed AETHER X;
- a developer ecosystem exists at production scale.

## 11. No Support Promise

Public documentation and issue intake do not create:

- guaranteed response times;
- maintenance windows;
- backward-compatibility duration;
- long-term support commitments;
- incident-response SLA;
- package release commitments.

Any future support policy requires separate explicit approval.

## 12. Intended Evaluation Use

The current public surface is appropriate for:

- technical inspection;
- reproducibility review;
- bounded contract evaluation;
- public reference experimentation;
- conformance review;
- developer-experience evaluation;
- architecture and governance discussion.

Any broader use must respect the repository's licensing/reuse boundary and the absence of supported-SDK authority.
